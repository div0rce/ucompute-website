Run models

Every model comes from a pinned catalog with a fixed revision, SHA-256 and license, or from a GGUF file you import yourself. Nothing is substituted behind your back.

Check your hardware

common hardware          # CPU, memory, GPU, backend and free disk
common hardware --json   # the same, machine-readable

The model catalog

common models list                 # size, license and whether it fits on this machine
common models search qwen
common models inspect qwen2.5-0.5b-instruct-q4_k_m
common models pull qwen2.5-0.5b-instruct-q4_k_m   # shows the license, asks, downloads and verifies

Downloads use HTTPS only, resume after interruption and are checked against the pinned SHA-256 before they are kept. Add -y to pull to accept the license without the prompt.

The two stories models are tiny test fixtures. Their license is unverified, so they are downloaded for tests and never bundled. They write short children's stories and are not useful for real work.

Your own GGUF files

common models import ./my-model.gguf --id my-model --license "Apache-2.0"
common models verify my-model
common models rm my-model

Run a prompt

common run qwen2.5-0.5b-instruct-q4_k_m --chat -p "Explain unified memory in two sentences."
common chat qwen2.5-0.5b-instruct-q4_k_m     # interactive; type /quit to leave
Options for common run
OptionDefaultMeaning
-p, --promptrequiredThe prompt text
--chatoffSend the prompt as a chat message so the model's chat template applies
-n, --max-tokens256Maximum tokens to generate
--deviceautoauto, cpu or gpu
--ctxset by the memory planContext length, capped to the model's trained context with a stated reason
--threadsengine's choiceEngine threads; the run manifest records what ran
--temp, --top-p, --seed0.7, 0.95, randomSampling; the manifest records the seed that ran
--save-promptoffAlso store the prompt text in the run manifest, so common replay can repeat it
--peernoneRun on a paired device instead (see Trusted devices). Can't be combined with --device, --ctx or --threads.

Every flag of every command is in the command-line reference.

With --device auto the GPU is used when the engine can offload to it (Metal on a Mac). If it can't, the run falls back to the CPU and tells you why. If a model will not fit in memory, it is refused with insufficient_memory before loading.

Benchmarks and replay

common bench qwen2.5-0.5b-instruct-q4_k_m --runs 3 -n 64   # writes results under ./benchmarks/results/
common replay ~/Library/Application\ Support/Common/runs/<run>/manifest.json

Benchmark results record the hardware, command line and versions with every number. Small-model results don't predict how large models behave.

In the desktop app

The app shows the same catalog with size, license and a fit verdict for this computer; that was demonstrated on an Apple M2 Mac (macOS 26.2), and memory-fit estimates are calibrated for Apple Silicon Macs.{{claim:catalog}}{{claim:memory-fit}} Its chat runs the loaded model, and on a computer with trusted devices enabled you can pick a paired device to run on. Tested between one Apple M2 Mac and one Windows 11 laptop (Intel Arc 140V) on the same Wi-Fi network or phone hotspot, with development builds; pairing has been shown starting from either of the two. Pairing between two Macs is not yet shown to work.{{claim:mesh-pair-choose}}
