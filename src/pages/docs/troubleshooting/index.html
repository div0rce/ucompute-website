Troubleshooting

Start with common doctor. Every error then carries a stable code and a hint; this page explains the ones people meet most.

Run common doctor

It changes nothing and downloads nothing. It prints the version and data folder, your hardware, whether the engine is present and verified, and the models you have, then a warning for each problem it finds:

  • engine is not ready: run `common setup`
  • low disk, when less than 2 GB is free
  • low available memory, when less than 1 GB is available; close other apps before loading large models

If all is well it ends with ok no problems found. Add --json for a machine-readable version.

A device doesn't appear under Nearby

Discovery uses mDNS, which many campus and office networks block between clients. On one university network neither the operating systems nor UCompute could see the other machine; on a phone hotspot both appeared within about a second. Use home Wi-Fi or a hotspot, or skip discovery and pair by address with Join a device.

Pairing or requests time out between a Mac and Windows

  • On Windows, allow the app on Private networks and make sure the network profile is Private.
  • Open the pairing window on the Mac and join from Windows. When Windows opens the window, Windows Firewall currently drops the connection.
  • On a Mac, the firewall in System Settings, Network, must allow incoming connections for the app to serve requests.

macOS won't open the app

Development builds are ad-hoc signed and not notarized. Allow the app once in System Settings, Privacy & Security.

Port 8192 is already in use

The desktop app checks GET /health on 127.0.0.1:8192 first and reuses a daemon that already answers. If something else holds the port, stop it or start your own daemon with --port.

Reporting a problem safely

common doctor --json
common diagnostics --out diagnostics.json   # redacted: no prompt text

Attach those, the exact command and your platform. Never include prompts, answers or credentials. Never report a suspected security problem publicly; see the security policy.
