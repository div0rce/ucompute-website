Troubleshooting

Start with common doctor. Every error then carries a stable code and a hint; this page explains the ones people meet most.

Run common doctor

It changes nothing and downloads nothing. It prints the version and data folder, your hardware, whether the engine is present and verified, and the models you have, then a warning for each problem it finds:

  • engine is not ready: run `common setup`
  • low disk, when less than 2 GB is free
  • low available memory, when less than 1 GB is available; close other apps before loading large models

If all is well it ends with ok no problems found. Add --json for a machine-readable version.

A device isn't found on the network

Discovery uses mDNS, which some campus Wi-Fi blocks between clients. On one university network neither the operating systems nor UCompute could see the other machine; on a phone hotspot both appeared within about a second (one Apple M2 Mac and one Windows 11 laptop, development builds, October 2026).{{claim:discovery}} If a device isn't found, pair or connect by address.

Pairing or requests time out between a Mac and Windows

  • On Windows, allow the app on Private networks and make sure the network profile is Private.
  • On Windows, approve the app's request to let paired devices reach it on private networks; {{q:firewall}} Development builds from before 22 October 2026 lack this step: with them, open the pairing window on the Mac and join from Windows.{{claim:firewall-consent}}
  • On a Mac, the firewall in System Settings, Network, may block incoming connections (suspected, not confirmed); if the Mac cannot serve requests, allow the app there.

macOS won't open the app

Development builds are ad-hoc signed and not notarized. Allow the app once in System Settings, Privacy & Security.

Port 8192 is already in use

The desktop app checks GET /health on 127.0.0.1:8192 first and reuses a daemon that already answers. If something else holds the port, stop it: the desktop app only uses port 8192.

Reporting a problem safely

common doctor --json
common diagnostics --out diagnostics.json   # redacted: no prompt text

Once the source is published and issues open, attach those, the exact command and your platform. Never include prompts, answers or credentials. Never report a suspected security problem publicly; see the security policy.
