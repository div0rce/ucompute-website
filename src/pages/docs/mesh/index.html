Trusted devices

UCompute Mesh lets one computer send a whole request to another computer you have paired and allowed. It is experimental, off by default, and limited to devices on the same local network.

What it does not do yetOne request runs on one device. Mesh does not split a model across devices, and it does not connect devices across the internet.

Before you start

  • Install UCompute on both computers and put them on the same network. Home Wi-Fi and phone hotspots work. Campus and office networks often block the multicast traffic that discovery needs; on those, pair by address instead.
  • Peer traffic uses UDP port 8193 by default. On Windows, allow the app through Windows Firewall on Private networks. A Mac whose firewall blocks incoming connections cannot serve requests.
  • Read what the other device can see. When a paired device runs your request, it decrypts the prompt and runs the model on it in plain text. It can read, log or keep the prompt and the answer.

1. Turn on trusted devices

In the app, open Privacy, choose trusted devices and acknowledge the disclosure. From the command line:

ucompute privacy trusted-devices      # shows the disclosure and asks y/N; --yes accepts it
ucompute privacy                      # shows the current mode

This also turns on peer networking. The public option exists in the app only as a disabled placeholder.

2. Start networking

In the app, switch networking on under Peers. A daemon you run yourself needs:

ucompute serve --network --serve-peers   # both settings are saved, not just for this run

Use --serve-peers only on a computer that should run work for others.

3. Pair

Open the pairing window on one computer and join from the other. The window lasts 120 seconds, and more than five wrong codes within a minute lock it.

  1. On the first computer: Peers, then Pair this device. It shows a six-digit code, the address to dial and a QR payload.
  2. On the second computer: Peers, find the first one under Nearby, not paired and choose Pair, or use Join a device with the address. Enter the code and choose Join.
  3. Both now list each other under Paired devices as Connected.
Pairing a Mac and a Windows PCOpen the pairing window on the Mac and join from Windows. When Windows opens the window, Windows Firewall currently drops the connection. This is a known issue.

From the command line:

ucompute peers discover               # devices advertising nearby; untrusted until paired
ucompute peers pair                   # first computer: shows the code and waits (Ctrl-C cancels)
ucompute peers join 192.168.1.20:51234 123456   # second computer: pairing address and code
ucompute peers list

4. Allow it in a group, on both computers

Pairing proves identity. It does not grant permission. A device can only run work for a device in the same group, and only what the group allows. Both computers check.

ucompute groups create home --allow-remote
ucompute groups add home 1a2b-3c4d-5e6f
ucompute groups policy home --allow-remote=false   # take it back later

In the app, Groups on the Peers screen has the same switches. The pooled-inference permission is reserved for milestone M4 and does nothing useful yet.

5. Run on the other device

In Chat, pick the device under Run on; the reply says where it ran. From the command line or your own code:

ucompute run qwen2.5-0.5b-instruct-q4_k_m --chat -p "Hello" --peer 1a2b-3c4d-5e6f

curl -s http://127.0.0.1:8192/v1/completions -H 'Content-Type: application/json' \
  -H 'X-UCompute-Target: peer:1a2b-3c4d-5e6f' \
  -d '{"model": "stories15M-q4_0", "prompt": "Once upon a time", "max_tokens": 32}'

The serving device needs the same model file, identified by SHA-256. If its copy differs it refuses with integrity_mismatch rather than running something else.

Remove or revoke a device

ucompute peers rm 1a2b-3c4d-5e6f       # forget it; it may pair again later
ucompute peers revoke 1a2b-3c4d-5e6f   # signed revocation; its key is refused from now on

Revoking closes every connection to the device, tells the devices that shared a group with it, and makes its key fail inside the encrypted handshake. In tests the revoked device was disconnected within 0.07 seconds.

See what happened

ucompute audit --n 20                       # recent pairing, policy and remote-request events
ucompute diagnostics --out diagnostics.json # a redacted bundle to attach to a bug report

Both sides audit each remote request with the same request id. The audit log holds ids, counts, codes and timings, never prompt or answer text.
