API reference

The daemon serves an OpenAI-compatible HTTP API on http://127.0.0.1:8192. The authoritative description is the OpenAPI 3.1 document at GET /openapi.json; a test keeps it identical to the routes the server serves.

Security defaults

  • Listens on 127.0.0.1 only. A non-loopback --host without --api-key is refused before anything is bound.
  • With an API key, every route except /health needs Authorization: Bearer <key>. A wrong or missing key gets 401 unauthorized.
  • Browser requests from origins other than the desktop app (tauri://localhost, http://tauri.localhost, https://tauri.localhost) and its development server (http://localhost:1420) are refused with 403.
  • Request bodies are capped at 2 MiB. Generation slots and the queue are bounded: 429 when full, 503 when a wait times out.
  • The engine's own port is never exposed, and prompts never appear in logs or metrics.

The target extension

POST /v1/chat/completions and POST /v1/completions accept "target" in the body or X-Common-Target as a header; the body wins.

  • "local", missing or empty: run here.
  • "peer:<64-hex id or short label>": run the whole request on that paired device. It is never split.

Every response and every streamed chunk carries "target". A peer target on embeddings, or a malformed one, is invalid_request. Browser clients must use the body field, because the header is not in the allowed CORS headers.

Turning on trusted devices

  1. GET /api/privacy returns mode and disclosure. Show the disclosure to the user.
  2. PUT /api/privacy {"mode": "trusted_group"} without acknowledgement returns 403 policy_denied, with the disclosure as the message.
  3. PUT /api/privacy {"mode": "trusted_group", "acknowledged": true} succeeds and is saved.
  4. {"mode": "local_only"} always succeeds. {"mode": "swarm_allowed"} is refused until its security gate.

Compatibility

This is API v1.0.0 of a development build. The official OpenAI Python and JavaScript clients are tested, on an Apple M2 Mac (macOS 26.2), for model listing, completions, chat, streaming and typed errors; that is a tested subset, not a claim of complete OpenAI compatibility. Tool calling is not yet verified.{{claim:openai-clients}} No compatibility window is promised until a beta release publishes one.
