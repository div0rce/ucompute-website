Computing that isn't confined to one machine.

The laptop you work on and the desktop with a capable GPU sit a metre apart and can't help each other. Every application that wants more compute builds its own networking, authentication and scheduling, or sends your data to someone else's servers. UCompute exists to change that, carefully.

An open computing layer

The goal is a layer that lets applications use authorized computing resources across supported devices, operating systems and networks, including applications that this project doesn't write or control.

It has three parts. A portable runtime runs supported work on each device and enforces its owner's policy. An open protocol lets devices identify each other, agree what is allowed and exchange work, written down well enough that someone else can implement it. A scheduler decides where work should run, and says when the answer is “right here”.

Linux is the inspiration for the openness, portability and ecosystem reach. UCompute is not trying to replace an operating system. It runs across them.

Every device plays a role

The specification defines four roles. A device can hold several, and none requires a GPU.

  • Consumer: submits work it is permitted to submit.
  • Provider: executes supported kinds of work for authorized consumers.
  • Coordinator: plans and supervises authorized work across providers.
  • Relay: carries encrypted traffic but can never authorize computation itself.

Today a Mac and a Windows laptop act as consumer and provider for each other. There is no general coordinator or public relay yet.

Adoption is planned as experiments, not assumed. Each stage names what would prove it wrong.

One network, one credit system

Strategic hypothesis

The economic direction being specified now: one computing network and one compute-credit system, with contributors in control of their hardware.

  • Contribute compute, earn compute. Capacity you choose to share, within limits you set, would earn credits.
  • Buy compute when you need more. Credits would be spent, or eventually bought, only through resource-sharing arrangements you have explicitly authorized.
  • Contributors decide. You would choose whether your capacity serves paid requests. Capacity given only as a donation would never be sold.
  • The core stays free. Run and private Mesh remain free and open source. Cloud would be an optional managed service, never a requirement.
None of this exists yetThere are no credits, purchases or payments today. The public Swarm is not operating, and UCompute Cloud is not a deployed service. The current specification enables no payment, transferable token or public credit promise, and any settlement needs separate technical, abuse and legal decisions first. No cryptocurrency.

Principles and non-goals

Local-first. Accounts optional. Secure by default: the API binds to this computer only, the engine's port is never exposed, and prompts are never logged. No silent substitution of a model, precision or privacy mode. No fabricated benchmarks. No cryptocurrency.

Not on the plan for current delivery: a new operating system, custom inference kernels, running arbitrary downloaded programs, public anonymous access, mandatory accounts or tokens, always-on servers on phones, or claims that any model runs on any device.
