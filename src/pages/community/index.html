Early, small, and saying so.

UCompute has no forum, chat server, mailing list or events yet, and this page won't pretend otherwise. Here is how you can take part today, and what to expect when you do.

Ways to take part

Follow the repository

Watch div0rce/common on GitHub to see the code and evidence as they are published.

Report what you find

Open an issue with the exact command, your platform, and the output of common doctor --json and common diagnostics. Never include prompts, answers or credentials.

What to include

Report security problems privately

Use private vulnerability reporting, not a public issue.

Security policy

Take a work package

Separable packages such as Linux support, SDKs or an independent protocol implementation can be picked up once the source is public.

Work packages

Qualify your hardware

Every new platform, GPU or device pair needs its own recorded evidence before it can be called supported. Running the documented checks on hardware the project doesn't have is one of the most useful contributions.

Propose a decision

Architectural changes start as a written decision record, reviewed in the open.

How decisions are made

What to expect

Issues are triaged by reproducible impact. During a beta the target is a first response within seven days, and the project will say plainly when volunteer capacity can't meet it. Security reports follow their own timeline.

Testers are recruited only with consent. Your devices, prompts and contact details are never treated as a marketing list, and analytics stay off by default in the software.

Everyone follows the code of conduct.

Not here yet

No Discord or Slack, no newsletter, no forum, no events, no sponsorship programme and no community metrics. When any of these exists, it will be linked from this page.
