Build on the compute people already have.

A local-first execution interface for supported models and authorized devices. Your application talks to the UCompute daemon over the OpenAI-compatible HTTP API it may already use, and decides explicitly where each request runs.

Quickstart

  1. Install and set up

    Once the source is published, build the common command (see Install), then run common setup to download and verify the pinned engine.

  2. Get a model

    common models pull qwen2.5-0.5b-instruct-q4_k_m shows the license, then downloads and verifies 491 MB.

  3. Start the daemon

    common serve listens on http://127.0.0.1:8192. The desktop app starts the same daemon for you.

  4. Call it

    Use the official OpenAI Python or JavaScript client with the base URL changed. The model loads on the first request. Demonstrated on an Apple M2 Mac (macOS 26.2); the platform is experimental.{{claim:openai-clients}}

# pip install openai
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8192/v1", api_key="unused-on-loopback")

stream = client.chat.completions.create(
    model="qwen2.5-0.5b-instruct-q4_k_m",
    messages=[{"role": "user", "content": "Explain unified memory in two sentences."}],
    stream=True,
)
for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
// npm install openai
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://127.0.0.1:8192/v1",
  apiKey: "not-needed-on-loopback",
});

const stream = await client.chat.completions.create({
  model: "qwen2.5-0.5b-instruct-q4_k_m",
  messages: [{ role: "user", content: "Explain unified memory in two sentences." }],
  stream: true,
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? "");
}

Choosing where it runs

Chat and completion requests accept one extension, target:

  • "local" runs here. It is the default; a missing or empty value means local.
  • "peer:<id>" runs the whole request on that paired device. The id is the 64-hex peer id or its xxxx-xxxx-xxxx short label.

Send it in the JSON body, or as the X-Common-Target header; the body wins when both are present. Every response and every streamed chunk carries "target", so nothing runs elsewhere silently. Embeddings always run locally.

curl -s http://127.0.0.1:8192/v1/completions -H 'Content-Type: application/json' \
  -H 'X-Common-Target: peer:1a2b-3c4d-5e6f' \
  -d '{"model": "stories15M-q4_0", "prompt": "Once upon a time", "max_tokens": 32}'

A peer target is refused with policy_denied or peer_unauthorized unless trusted devices are enabled, networking is on, the device is paired and a group on both sides allows it. With the Python client, pass extra_body={"target": "peer:…"}.

{"object": "chat.completion",

The contract

Routes

OpenAI-compatible: GET /v1/models, POST /v1/chat/completions, POST /v1/completions, POST /v1/embeddings. UCompute's own routes live under /api: hardware, status, the model catalog with a per-model memory fit verdict, downloads with progress, loading and unloading, and the trusted-device routes. The versioned OpenAPI 3.1 document is served at GET /openapi.json, and a test keeps it identical to the routes the server actually serves.

Errors

Every error uses the OpenAI shape, with a stable code from a fixed list and a hint:

{"error": {"message": "…", "type": "…", "code": "model_not_downloaded", "param": null, "hint": "…"}}

Authentication and browsers

On loopback no key is needed. Listening on any other address requires --api-key, and then every route except /health needs Authorization: Bearer <key>. Browser origins other than the desktop app's are refused.
