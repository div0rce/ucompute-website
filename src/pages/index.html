Two computers.
One request.

In a test on 19 October 2026, development builds of the desktop app on a MacBook Air and a Windows laptop were paired through their own windows on one phone hotspot, and the Windows app ran a prompt on the Mac. A request in the other direction, sent through the Mac's local API rather than its app window, ran on the laptop's GPU. Nothing on this page is an animation of work that didn't happen.{{claim:demo-2026-10-19}}

  1. Pair

    The Mac shows a six-digit code. The laptop finds the Mac on the local network and joins with the code. A wrong code is refused.

  2. Allow

    Each machine puts the other in a group that may run prompts. Without that, on both sides, nothing runs remotely. On the Mac this was set through its local API, not its window.

  3. Choose

    In the laptop's chat, the paired Mac can be chosen as the device to run on. The request goes to the device you pick and never silently anywhere else.

  4. Run

    The request crosses UCompute's own QUIC connection, encrypted with TLS 1.3 and pinned device keys. The Mac loads the model on demand and runs it on its GPU. Both sides log the request without its text.

  5. Read the result

    112 tokens. First token after 2,325 ms, including loading the model on the Mac. 508 tokens a second on the stories15M test fixture: a path check, not a performance figure.

Remote execution, not pooling. One whole request ran on one other machine. No model has been split across devices; that is planned and not started.{{claim:planned}}

Verified for these development builds and this hardware only. It is not an offer to download them.{{claim:demo-2026-10-19}}{{claim:no-release}}

Developer guide

One API.
Real possibilities.

The daemon speaks the OpenAI-compatible HTTP API that existing clients already use. One extra field, target, chooses where a request runs, and every response says where it ran.

  • Official OpenAI Python and JavaScript clients

    They work with only the base URL changed: chat and completions with streaming. Tool calling is not yet verified.{{claim:openai-clients}}

  • Streaming and typed errors

    Server-sent events, and one error shape with stable codes.

  • Local unless you say otherwise

    Listens on 127.0.0.1. A peer target is refused unless policy allows it.

# Runs on this computer
curl http://127.0.0.1:8192/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model": "qwen2.5-0.5b-instruct-q4_k_m",
       "messages": [{"role": "user", "content": "Hello"}],
       "stream": true}'

# Runs the whole request on a paired device
curl http://127.0.0.1:8192/v1/completions \
  -H 'Content-Type: application/json' \
  -H 'X-Common-Target: peer:1a2b-3c4d-5e6f' \
  -d '{"model": "stories15M-q4_0", "prompt": "Once upon a time", "max_tokens": 32}'
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8192/v1", api_key="unused-on-loopback")

reply = client.chat.completions.create(
    model="qwen2.5-0.5b-instruct-q4_k_m",
    messages=[{"role": "user", "content": "Hello"}],
)
print(reply.choices[0].message.content)

# Run the whole request on a paired device instead
remote = client.chat.completions.create(
    model="qwen2.5-0.5b-instruct-q4_k_m",
    messages=[{"role": "user", "content": "Hello"}],
    extra_body={"target": "peer:1a2b-3c4d-5e6f"},
)
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://127.0.0.1:8192/v1",
  apiKey: "not-needed-on-loopback",
});

const stream = await client.chat.completions.create({
  model: "qwen2.5-0.5b-instruct-q4_k_m",
  messages: [{ role: "user", content: "Hello" }],
  stream: true,
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? "");
}

Local examples follow the repository's client smoke tests. The peer target is documented in the API reference; use a label from GET /api/peers.

Share your compute.
Not your computer.

Our direction: the headline is the design goal for sharing with others, and the isolation that would make it safe with strangers is not built yet.{{claim:direction}} What protects you today, between devices you pair and trust, is below. Each item is verified with recorded engineering evidence for the development builds.

Trust boundaries and security reports

Local by default

The API listens on 127.0.0.1 only. Peer networking and discovery stay off until you turn them on. Downloading a model or the engine uses the internet.{{claim:run-local}}{{claim:local-only}}

Permission, not assumption

A device needs a one-time pairing code, a group that allows remote runs, and permission on both ends. Devices you have not paired cannot send you work or receive yours, and a revoked device is cut off.{{claim:transport}}{{claim:groups}}{{claim:revocation}}

Honest about the risk

The device that runs your request processes your prompt. It can read, log or keep the prompt and the answer, so pair only devices you control or trust. You see this before trusted devices can be enabled.{{claim:device-sees-prompt}}{{claim:local-only}}

Prompts stay out of logs

Audit logs record each off-device request without the prompt or the response.{{claim:audit}}

Public compute waits

Running work for strangers stays disabled until isolation, verification and abuse protections pass independent review.{{claim:planned}}
