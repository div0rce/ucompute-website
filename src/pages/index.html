Two computers.
One request.

On 19 October 2026 we paired two installed development builds through their own screens, on one phone hotspot, and ran prompts in both directions. Nothing on this page is an animation of work that didn't happen.

  1. Pair

    The Mac shows a six-digit code under Peers, Pair this device. The laptop finds the Mac under Nearby, not paired, and joins with the code. A wrong code is refused.

  2. Allow

    Each machine puts the other in a group that may run prompts. Without that, on both sides, nothing runs remotely.

  3. Choose

    In Chat, Run on lists the paired Mac. The request goes to the device you pick and never silently anywhere else.

  4. Run

    The request crosses UCompute's own QUIC connection, encrypted with TLS 1.3 and pinned device keys. The Mac loads the model on demand and runs it on its GPU. Both sides log the request without its text.

  5. Read the result

    112 tokens. First token after 2,325 ms, including loading the model on the Mac. 508 tokens a second on the stories15M test fixture: a path check, not a performance figure.

Remote execution, not pooling. One whole request ran on one other machine. No model has been split across devices yet; that is milestone M4.

Verified for these builds and this hardware only, not an offer to download them. Evidence: docs/evidence/desktop-two-machine-2026-10-19.md at af3e37c.

Developer guide

One API.
Real possibilities.

The daemon speaks the OpenAI-compatible HTTP API that existing clients already use. One extra field, target, chooses where a request runs, and every response says where it ran.

  • Official OpenAI Python and JavaScript clients

    Tested against the daemon with only the base URL changed.

  • Streaming and typed errors

    Server-sent events, and one error shape with stable codes.

  • Local unless you say otherwise

    Listens on 127.0.0.1. A peer target is refused unless policy allows it.

# Runs on this computer
curl http://127.0.0.1:8192/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model": "qwen2.5-0.5b-instruct-q4_k_m",
       "messages": [{"role": "user", "content": "Hello"}],
       "stream": true}'

# Runs the whole request on a paired device
curl http://127.0.0.1:8192/v1/completions \
  -H 'Content-Type: application/json' \
  -H 'X-Common-Target: peer:1a2b-3c4d-5e6f' \
  -d '{"model": "stories15M-q4_0", "prompt": "Once upon a time", "max_tokens": 32}'
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8192/v1", api_key="unused-on-loopback")

reply = client.chat.completions.create(
    model="qwen2.5-0.5b-instruct-q4_k_m",
    messages=[{"role": "user", "content": "Hello"}],
)
print(reply.choices[0].message.content)

# Run the whole request on a paired device instead
remote = client.chat.completions.create(
    model="qwen2.5-0.5b-instruct-q4_k_m",
    messages=[{"role": "user", "content": "Hello"}],
    extra_body={"target": "peer:1a2b-3c4d-5e6f"},
)
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://127.0.0.1:8192/v1",
  apiKey: "not-needed-on-loopback",
});

const stream = await client.chat.completions.create({
  model: "qwen2.5-0.5b-instruct-q4_k_m",
  messages: [{ role: "user", content: "Hello" }],
  stream: true,
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? "");
}

Local examples follow the repository's client smoke tests. The peer target is documented in the API reference; use a label from GET /api/peers.

Security policy and threat model

Local by default

The API listens on 127.0.0.1 only. Peer networking and discovery stay off until you turn them on. F-06-06, F-10-10

Permission, not assumption

A device needs a one-time pairing code, a group that allows remote runs, and permission on both ends. A revoked key is refused inside the encrypted handshake. F-02-02, F-06-02, F-06-05

Honest about the risk

A paired device decrypts your prompt and runs the model on it in plain text. It can read, log or keep the prompt and the answer. You see this before trusted devices can be enabled. F-06-07

Prompts stay out of logs

Audit entries record ids, counts, codes and timings, never prompt or answer text. F-06-10

Public compute waits

Running work for strangers stays disabled until isolation, verification and abuse protections pass independent review. Gate F; F-06-08 not started
