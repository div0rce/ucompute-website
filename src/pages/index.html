One request.
Two computers.

In a test on 19 October 2026 (UTC), development builds of the desktop app on a MacBook Air (Apple M2, macOS 26.2) and a Windows 11 laptop (Intel Core Ultra 7 258V, Arc 140V) were paired through their own windows on one phone hotspot, and the Windows app ran a prompt on the Mac (the Mac's permission for the laptop to run prompts was set through the Mac's local API, not its window). A request in the other direction, sent through the Mac's local API rather than its app window, ran on the laptop's GPU. Each request ran whole on one device; no model was split. The test model was a 15-million-parameter fixture, so speeds from it are not performance figures.{{claim:demo-2026-10-19}}

  1. Pair

    The Mac shows a six-digit code. The laptop finds the Mac on the local network and joins with the code. A wrong code is refused.

  2. Allow

    Each machine puts the other in a group that may run prompts. Without that, on both sides, nothing runs remotely. On the Mac this was set through its local API, not its window.

  3. Choose

    In the laptop's chat, the paired Mac can be chosen as the device to run on. The request goes to the device you pick, and the response says where it ran.

  4. Run

    The request crosses UCompute's own QUIC connection, encrypted with TLS 1.3 and pinned device keys. The Mac loads the model on demand and runs it on its GPU. Both sides log the request without its text.

  5. Read the result

    112 tokens. First token after 2,325 ms, including loading the model on the Mac. 508 tokens a second on the stories15M test fixture: a path check, not a performance figure.

    Remote execution, not pooling. One whole request ran on one other machine. No model has been split across devices; that is planned and not started.{{claim:planned}} Hardware, timings, open issues

What exists today sits at the centre: Run, with Mesh around it. Each ring further out is planned, and is marked that way until it is built and verified.

  1. UCompute Run

    Experimental

    UCompute Run runs small open models on your own computer, with no account and no UCompute service. By default, your requests stay on your device. {{q:run-local}}{{claim:run-local}}{{claim:platforms}}

  2. UCompute Mesh

    Experimental

    UCompute Mesh lets you pair your own devices with a short code and choose which one runs a request. Each request runs whole on one device; UCompute does not split a model across devices. {{q:mesh}}{{claim:mesh-pair-choose}}

  3. One model across devices

    Planned

    One model split across several devices, each computing part of every token. Planned and not started.{{claim:planned}}

  4. UCompute Swarm

    Planned

    An opt-in open network, disabled until isolation, metering, verification and abuse protections pass independent review.{{claim:planned}}

  5. UCompute Cloud

    Planned

    An optional managed service. It does not exist today, and it would never be required for local or private use.{{claim:planned}}

One API.
Real possibilities.

The daemon speaks the OpenAI-compatible HTTP API that existing clients already use. One extra field, target, chooses where a request runs, and every response says where it ran.

  • Official OpenAI Python and JavaScript clients

    They work with only the base URL changed: chat and completions with streaming. Tool calling is not yet verified. Demonstrated on an Apple M2 Mac (macOS 26.2); the platform is experimental.{{claim:openai-clients}}

  • Streaming and typed errors

    Server-sent events, and one error shape with stable codes.

  • Local unless you say otherwise

    Listens on 127.0.0.1. A peer target is refused unless policy allows it. Running on a paired device: {{q:mesh}}{{claim:mesh-pair-choose}}

# Runs on this computer
curl http://127.0.0.1:8192/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model": "qwen2.5-0.5b-instruct-q4_k_m",
       "messages": [{"role": "user", "content": "Hello"}],
       "stream": true}'

# Runs the whole request on a paired device
curl http://127.0.0.1:8192/v1/completions \
  -H 'Content-Type: application/json' \
  -H 'X-UCompute-Target: peer:1a2b-3c4d-5e6f' \
  -d '{"model": "stories15M-q4_0", "prompt": "Once upon a time", "max_tokens": 32}'
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8192/v1", api_key="unused-on-loopback")

reply = client.chat.completions.create(
    model="qwen2.5-0.5b-instruct-q4_k_m",
    messages=[{"role": "user", "content": "Hello"}],
)
print(reply.choices[0].message.content)

# Run the whole request on a paired device instead
remote = client.chat.completions.create(
    model="qwen2.5-0.5b-instruct-q4_k_m",
    messages=[{"role": "user", "content": "Hello"}],
    extra_body={"target": "peer:1a2b-3c4d-5e6f"},
)
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://127.0.0.1:8192/v1",
  apiKey: "not-needed-on-loopback",
});

const stream = await client.chat.completions.create({
  model: "qwen2.5-0.5b-instruct-q4_k_m",
  messages: [{ role: "user", content: "Hello" }],
  stream: true,
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? "");
}

Local examples follow the repository's client smoke tests. The peer target is documented in the API reference; use a label from GET /api/peers.

Trust boundaries and security reports

Local by default

The API listens on 127.0.0.1 only. Peer networking and discovery stay off until you turn them on. Downloading a model or the engine uses the internet.{{claim:run-local}}{{claim:local-only}}

Permission, not assumption

A device needs a one-time pairing code, a group that allows remote runs, and permission on both ends. Your device will not send work to a device you have not paired, and a revoked device is cut off.{{claim:transport}}{{claim:groups}}{{claim:revocation}} A device you have not paired cannot send you work; that was tested with several instances on one computer, not yet between two machines.{{claim:unpaired-inbound}}

Honest about the risk

The device that runs your request processes your prompt. It can read, log or keep the prompt and the answer, so pair only devices you control or trust. You see this before trusted devices can be enabled.{{claim:device-sees-prompt}}{{claim:local-only}}

Prompts stay out of logs

Audit logs record each off-device request without the prompt or the response.{{claim:audit}}

Public compute waits

Running work for strangers stays disabled until isolation, verification and abuse protections pass independent review.{{claim:planned}}
