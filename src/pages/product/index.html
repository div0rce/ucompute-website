Run a model here, or on a device you trust.

UCompute is one open foundation offered four ways. Run and Mesh exist today in development builds. Swarm and Cloud are planned, with no date, and stay switched off until they can be made safe and useful. Each UCompute name maps one-to-one to the Common name used in the code: UCompute Run is Common Run, and so on.

What the status labels mean

UCompute Run

Your AI.
Your machine.

Experimental

Install, pick a model, press Run. No account and no cloud: the model runs on the computer in front of you, through a desktop app, a command-line tool, or an OpenAI-compatible API on 127.0.0.1:8192.

Works today

  • Real GGUF models through a pinned, hash-verified build of the llama.cpp engine, on CPU and on Apple Metal. The Windows build runs the same engine on Intel Arc through Vulkan. F-01-02, F-01-04 verified
  • A catalog of eight pinned models, each with its revision, SHA-256 and license. The license is shown before every download. F-01-05, F-05-01, F-05-04 verified
  • A memory check before loading. On 14 measured model and context combinations the estimate was within −4.6% to +8.9% of the engine's real footprint. F-01-03 verified
  • Streaming, cancellation, and one error format with stable codes. F-09-02, F-08-02, F-08-03 verified
  • No silent substitutions: if a model, quantization or GPU isn't available, you are told why instead of being given something else. F-01-04, F-10-06 verified

Not yet

  • A signed public installer for any platform. Mac builds are ad-hoc signed and Windows builds unsigned; neither is released. F-10-01 implemented, unverified; B-008
  • Linux execution, a second inference engine, and a verified tool-calling round trip. WP-03; F-01-06, F-01-12 implemented, unverified
  • A fresh-account, interface-only first run on a clean Mac, which the desktop milestone still requires.

Run models: the guide

UCompute Mesh

Better
together.

Experimental

Pair computers you control, decide which ones may run work for each other, and send a whole request to the one with the right hardware. Everything is off until you turn it on.

Works today

  • Pairing with a six-digit code or a QR payload, bound to the encrypted session so a relay in the middle cannot complete it. More than five wrong attempts within a minute lock the window. F-02-02 verified
  • Each device holds its own Ed25519 key. Connections use QUIC with TLS 1.3 and pinned keys; a revoked key fails inside the handshake. F-06-01, F-02-03, F-06-03, F-06-05 verified
  • Groups decide who may run prompts, and both the sending and the serving device must agree. Peers get per-device quotas and can never take this device's last engine slot. F-02-09, F-06-02 verified; F-06-04 implemented, unverified
  • Discovery on the local network with signed mDNS adverts, or pairing by address when the network blocks multicast. F-02-01 verified
  • Recorded on two physical machines: a MacBook Air and a Windows laptop running each other's prompts, the Mac direction through its daemon API. See the evidence. F-10-05 implemented, unverified; evidence af3e37c

Not yet

  • Pooling: splitting one model across devices so they compute parts of it together. This is milestone M4 and has not started. F-03-01 not started
  • Connections across the internet, through NAT or relays. M9, WP-11
  • The promotion checks for a stable Mesh: default fairness when peers flood a device, Windows key-file protection, and many more independent pairs. WP-02; Stable Mesh cohort

Later, and only when it's safe

UCompute Swarm

Planned

Disabled, with no date. Opt-in contribution of spare capacity to people you don't know, with limits you set before any work is admitted. It stays disabled in the code until isolation, metering, verification and abuse protections pass an independent security review. No credits, payments or tokens exist today; a single compute-credit system is a future direction, not a product.

UCompute Cloud

Strategic hypothesis

Optional managed services built on the same open contracts, such as operated deployments for teams. No date, and no paid service is authorized; it is a business hypothesis to be tested with real users, not a product. Local and private use will never require an account or a subscription.

One foundation underneath

Core, Protocol, Scheduler and SDK are parts of the system, not separate products.

Core

Experimental

The runtime: hardware detection, model planning, verified artifacts, the supervised inference engine and the local API.

Protocol

Experimental

The local HTTP API and the peer profile. The peer profile has no stability promise until an independent implementation interoperates. U-01

Scheduler

Planned

Choosing where work should run from measured hardware, network and policy, and saying so when local is better. Today you choose the target yourself. M5, WP-05

SDK

Planned

Versioned Python and TypeScript clients. Until then, the official OpenAI clients work against the local API. F-09-05, U-04

How the pieces fit

Platforms

No platform is declared SUPPORTED. A Mac with Apple Silicon (an M2 with macOS 26.2) and a Windows 11 laptop with Intel Arc graphics have recorded evidence and are EXPERIMENTAL. Linux, other GPUs and mobile devices are planned and untested.
