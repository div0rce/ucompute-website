Pick a path.

UCompute has no public release yet. Each path below is what you can do today with development builds, step by step, and where it stops.{{claim:no-release}}

Run AI on your own computer

Experimental

For anyone who wants a model answering on their own machine, with the prompt staying there.{{claim:local-only}}

Demonstrated on an Apple M2 Mac (macOS 26.2) and a Windows 11 laptop with an Intel Arc 140V GPU; both platforms are experimental; other platforms are planned.{{claim:run-local}}{{claim:platforms}}

  1. Check your platform

    Nothing is released, and no platform is supported yet.

    Release status

  2. Build it from source

    Build the common command, and the desktop app if you want it.

    Install

  3. Set up the engine

    common setup downloads the pinned engine and checks its hash before use.

    Engine setup

  4. Download a model

    common models pull qwen2.5-0.5b-instruct-q4_k_m shows the license and size before it downloads.{{claim:catalog}}

    The catalog

  5. Get a first answer

    common run qwen2.5-0.5b-instruct-q4_k_m -p "Hello", or the Chat view in the desktop app.

    Run a prompt

Where it stops today. There is no signed installer, no first run from a fresh account through the app alone, and no qualified Linux support yet.{{claim:installer}}{{claim:not-yet-run}}

Connect a second computer you trust

Experimental

For people with a second computer they own, who want a request to run there instead, by their choice.

Tested between one Apple M2 Mac and one Windows 11 laptop (Intel Arc 140V) on the same Wi-Fi network or phone hotspot, with development builds; pairing has been shown starting from either of the two. Pairing between two Macs is not yet shown to work.{{claim:mesh-pair-choose}}

  1. Run UCompute on both

    Each computer needs its own working setup first.

    The first path

  2. Turn on trusted devices

    common privacy trusted-devices shows what changes and asks before it does. Local only is the default.{{claim:local-only}}

    Turn it on

  3. Pair with a six-digit code

    common peers pair on one computer shows a code; common peers join on the other enters it.{{claim:mesh-pair-choose}}

    Pair

  4. Allow it, on both computers

    A paired device can run nothing here until a group you made allows it.{{claim:groups}}

    Groups

  5. Run a request there

    common run <model> --peer <label> -p "Hello", or pick the device in the app.

    Run on the other device

  6. Revoke it at any time

    A revoked device is refused from then on, and the audit trail records what ran.{{claim:revocation}}{{claim:audit}}

    Revoke

Where it stops today. Pairing two Macs is not yet shown, connections beyond one local network are not built, and one model split across devices is planned.{{claim:not-yet-run}}{{claim:planned}}

Build on the local API

Experimental

For developers who want an OpenAI-style API on their own machine, and a say in which device runs each request.

The official OpenAI Python and JavaScript clients are tested, on an Apple M2 Mac (macOS 26.2), for model listing, completions, chat, streaming and typed errors; that is a tested subset, not a claim of complete OpenAI compatibility.{{claim:openai-clients}}

  1. Start the local API

    common serve listens on 127.0.0.1:8192: by default, on this computer only.

    Serve options

  2. Point a client at it

    Use the OpenAI client you already know, with a local base URL.

    Quickstart

  3. Choose where each request runs

    The target field keeps it here or sends it to a paired device, and every response says where it ran.

    Targets

  4. Handle errors by code

    Every error has a stable code and a plain-language message.{{claim:gpu-fallback}}

    Error codes

  5. Script the rest

    Every command, flag and environment variable, generated from the source.

    Command line

Where it stops today. There are no SDKs yet, tool calling is not verified, and no compatibility window is promised before a beta release.{{claim:not-yet-run}}
