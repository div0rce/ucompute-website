Run AI on your own computer

Experimental

For anyone who wants a model answering on their own machine, with the prompt staying there.{{claim:local-only}}

{{q:run-local}}{{claim:run-local}}{{claim:platforms}}

Engine and model downloads: demonstrated on an Apple M2 Mac (macOS 26.2); the platform is experimental.{{claim:catalog}}

  1. Check your platform

    Nothing is released, and no platform is supported yet.

    Release status

  2. See how it is built

    The ucompute command and the desktop app are built from source, which has not been published yet.{{claim:license}}

    Install

  3. Set up the engine

    ucompute setup downloads the pinned engine and checks its hash before use.

    Engine setup

  4. Download a model

    ucompute models pull qwen2.5-0.5b-instruct-q4_k_m shows the license and size before it downloads.{{claim:catalog}}

    The catalog

  5. Get a first answer

    ucompute run qwen2.5-0.5b-instruct-q4_k_m -p "Hello", or the Chat view in the desktop app.

    Run a prompt

Where it stops today. There is no signed installer and no first run from a fresh account through the app alone yet, and Linux is planned.{{claim:installer}}{{claim:platforms}}

Connect a second computer you trust

Experimental

For people with a second computer they own, who want a request to run there instead, by their choice.

{{q:mesh}}{{claim:mesh-pair-choose}}

  1. Run UCompute on both

    Each computer needs its own working setup first.

    The first path

  2. Turn on trusted devices

    ucompute privacy trusted-devices shows what changes and asks before it does. Local only is the default.{{claim:local-only}}

    Turn it on

  3. Pair with a six-digit code

    ucompute peers pair on one computer shows an address and a code; ucompute peers join <address> <code> on the other enters them.{{claim:mesh-pair-choose}}

    Pair

  4. Allow it, on both computers

    Another computer can run work here only after you pair it and allow it in a group.{{claim:groups}}

    Groups

  5. Run a request there

    ucompute run <model> --peer <label> -p "Hello". In the Windows app you can pick the Mac (shown on 19 October 2026); choosing from the Mac app's window is not shown yet.{{claim:demo-2026-10-19}}

    Run on the other device

  6. Revoke it at any time

    A revoked device is refused from then on. Audit logs record each off-device request without the prompt or the response.{{claim:revocation}}{{claim:audit}}

    Revoke

Where it stops today. Pairing two Macs is not yet shown, connections beyond one local network are not built, and one model split across devices is planned.{{claim:not-yet-run}}{{claim:planned}}

Build on the local API

Experimental

For developers who want an OpenAI-style API on their own machine, and a say in which device runs each request.

The official OpenAI Python and JavaScript clients are tested, on an Apple M2 Mac (macOS 26.2), for model listing, completions, chat, streaming and typed errors; that is a tested subset, not a claim of complete OpenAI compatibility.{{claim:openai-clients}}

Running a request on a paired device: {{q:mesh}}{{claim:mesh-pair-choose}}

  1. Start the local API

    ucompute serve listens on 127.0.0.1:8192: by default, on this computer only.

    Serve options

  2. Point a client at it

    Use the OpenAI client you already know, with a local base URL.

    Quickstart

  3. Choose where each request runs

    The target field keeps it here or sends it to a paired device, and every response says where it ran.

    Targets

  4. Handle errors by code

    Every error has a stable code and a plain-language message.{{claim:gpu-fallback}}

    Error codes

  5. Script the rest

    Every command and flag, and the environment variables you set, generated from the source.

    Command line

Where it stops today. There are no SDKs yet, tool calling is not verified, and no compatibility window is promised.{{claim:not-yet-run}}

Follow the project

Planned

For people who want to help build it. Contributions are planned for after the source is published.

The code is licensed under Apache-2.0. The source has not been published yet.{{claim:license}}

  1. Read the ground rules

    Real over fake, requirements tracked with evidence, secure by default, and licenses that matter. They apply to every contributor, human or AI.

    How contributions will work

  2. Follow the roadmap

    Fifteen milestones, counted against a requirements ledger, without dates.{{claim:ledger}}

    Roadmap

  3. Keep security problems private

    Never post a suspected vulnerability publicly. No tested private reporting route exists yet.

    Security policy

  4. Qualify your hardware

    Every new platform, GPU or device pair needs its own recorded evidence. Running the documented checks on hardware the project doesn't have is planned as one of the most useful contributions.

    Ways to take part

  5. Take a work package

    Separable pieces such as SDKs or an independent protocol implementation can be picked up once the source is public.{{claim:work-packages}}

    Work packages

Where it stops today. There is nothing to clone or send changes to until the source is published.{{claim:license}}
