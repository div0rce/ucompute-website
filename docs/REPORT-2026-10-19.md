## Launch readiness: what prevents a public launch of the complete site

1. **Source code is not published.** `div0rce/common` holds only the license and the brief. The Open source, Install and Community pages describe building from source and contributing.
2. **No tested security or conduct contact.** GitHub private vulnerability reporting is disabled on `div0rce/common`; the security policy requires a tested route and a named responder before external beta.
3. **No release to offer.** No WP-08 promotion record, no signed installers (B-008), no private-alpha cohort. The Download page correctly offers nothing.
4. **Naming and trademark clearance** for UCompute are open.
5. **Authorizations recorded.** Done: the engineering session recorded the website authorizations as D-020 (bfcf4a7). Each later public page or download still needs its own owner authorization.
6. **Content refresh** from the engineering capability snapshot and the defect fixes once committed (economics done at a3ac99a).
7. **Human checks** with a screen reader, in native Safari on macOS and iOS, and in the Firefox app. The automated engine checks passed on 2026-10-21 (Chrome, Playwright Firefox and Playwright WebKit; see `docs/VERIFICATION.md`).
8. Then, with the owner's approval: merge `preview` into `main`, set Production `UCOMPUTE_SITE=public`, redeploy, and run `verify-live.mjs` with the public expectations.
